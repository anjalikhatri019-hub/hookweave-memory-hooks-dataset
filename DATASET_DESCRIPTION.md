# HOOKWEAVE dataset description

## Purpose and intended use

HOOKWEAVE is a creator-owned, reproducibly generated synthetic benchmark for developing and comparing AI-agent memory-hook policies. The intended task is to use an episode of conflicting memory notes and its eight case-local hook candidates to choose two hooks in order, then compute the four resulting memory values and source-event indices from public events. The program choice is learned from training labels because utility depends on private final true values. It is suitable for benchmark experiments, method comparison, and teaching controlled memory-update reasoning. It is not a record of user conversations or a validation set for a deployed assistant.

## Data and split

There are 5,000 independent episodes. Each has 360 chronological events about 20 numbered memory slots, four later queries, and eight case-local hook candidates. An event is `[slot, reported_value, source_role, review_epoch, note]`; each note ends with a public `cross-checked` or `provisional` review marker. The 4,000 `train.jsonl` rows contain `case_id`, `events`, `query`, `candidates`, `oracle_program`, `oracle_answers`, and `oracle_evidence`. The 1,000 `test.jsonl` rows contain only `case_id`, `events`, `query`, and `candidates`; their optimal programs and private utilities are withheld. Train and test use disjoint reliability/drift regime *pairings* (20 train pairings and five test pairings) from the same synthetic generator. A train row's labels provide one optimal ordered hook pair, the four resulting values, and the four source-event indices. Every pair's utility is exactly its fraction of four private true values matched, with no hook-kind penalty; tied optimal pairs are equally correct. All 56 programs' resulting values and event indices are reconstructible from public events; private final true values are used only for utility scoring.

## File inventory and preparation

The platform's private organizer input, `raw_dataset.zip`, contains exactly `dataset_public.zip` and `private_answers.jsonl`. `private_answers.jsonl` carries one private grading record per test case and must not be shown to participants. Prepare extracts the participant archive into the public directory, converts the private records to `answers.csv` in the private directory, and creates public `sample_submission.csv`. The participant archive, also available at the dataset link below, contains exactly:

- `train.jsonl`: 4,000 newline-delimited JSON training episodes with supervised labels.
- `test.jsonl`: 1,000 newline-delimited JSON test episodes without labels.
- `manifest.json`: a compact dataset metadata record with `train_cases: 4000`, `test_cases: 1000`, `events_per_case: 360`, `topics: 20`, `split: "held-out regime pairings"`, `provenance: "creator-owned deterministic synthetic event corpus"`, and `license: "CC-BY-4.0"`. It contains no labels, seed, or per-case answers.
- `LICENSE_DATA.md`: the CC BY 4.0 notice for the generated dataset and documentation. It gives the license URL and suggested attribution, asks redistributors to link to the public source and indicate changes, and clarifies that private answers, generator, grader, and software code are outside this data-license grant.

The public prepared directory additionally contains `sample_submission.csv`; it is generated by Prepare and is not a member of `dataset_public.zip`. The participant ZIP is 299,407,834 bytes (about 299 MB). The source release contains this ZIP only; GitHub's automatic repository source archive is not the dataset.

## Known limitations

All episodes, notes, roles, review markers, and outcomes are generated. They do not model the full ambiguity, language variety, privacy issues, or changing user intent in real conversations. Public replay is exact, but final true values remain private labels, so the best program need not be identifiable with certainty from one test row. Training and test differ by held-out *combinations* of reliability and drift regimes, but both are drawn from the same generator, schema, vocabulary, and event length. A score on this split therefore measures transfer within this synthetic family; it does not establish performance on unseen generators, languages, real users, or production memory systems. The benchmark evaluates four queries after fixed-length episodes, not long-running agents with tool failures, consent handling, deletion requests, or adversarial instructions. The data should not be used to infer that a hook policy is safe to deploy without separate real-world evaluation.
