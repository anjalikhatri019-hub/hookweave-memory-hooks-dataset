# HOOKWEAVE dataset description

## Purpose and intended use

HOOKWEAVE is a creator-owned, reproducibly generated synthetic benchmark for developing and comparing AI-agent memory-hook policies. The intended task is to use an episode of conflicting memory notes and its eight case-local hook candidates to choose two hooks in order, then compute the four resulting memory values and source-event indices from public events. Each public case also provides its four target `goal_values`, so an exact solver can compare all 56 legal ordered pairs without hidden labels. It is suitable for benchmark experiments, method comparison, and teaching controlled memory-update reasoning. It is not a record of user conversations or a validation set for a deployed assistant.

## Data and split

There are 5,000 independent episodes. Each has 360 chronological events about 20 numbered memory slots, four later queries, and eight case-local hook candidates. An event is `[slot, reported_value, source_role, review_epoch, note]`; each note ends with a public `cross-checked` or `provisional` review marker. The 4,000 `train.jsonl` rows contain `case_id`, `events`, `query`, `goal_values`, `candidates`, `oracle_program`, `oracle_answers`, and `oracle_evidence`. The 1,000 `test.jsonl` rows contain `case_id`, `events`, `query`, `goal_values`, and `candidates`; they omit oracle labels. Train and test use disjoint reliability/drift regime *pairings* (20 train pairings and five test pairings) from the same synthetic generator. A train row's oracle fields provide one optimal ordered hook pair, the four resulting values, and the four source-event indices. Every pair's utility is exactly its fraction of four public `goal_values` matched, with no hook-kind penalty; tied optimal pairs are equally correct. All 56 programs' resulting values, event indices, and utilities are reconstructible from public test rows.

For each queried slot, `goal_values` selects the latest `cross-checked` report from the user role (0), falling back to the latest `cross-checked` report from any role, then to the latest report, then to `-1` if the slot has no report. This public source-priority rule does not depend on selected hooks. The organizer's grading records duplicate public-computable outcomes for verification; they contain no secret target needed to solve a test row.

Each case has one `capture` and one `restore` candidate with the same listed slot. `restore` checks its listed slot against the saved capture and writes only to that slot; without a matching prior capture it is a no-op. In a two-hook program, capture followed immediately by restore leaves the slot unchanged. These no-op choices let a participant meet the exactly-two-hooks contract when no second state change is useful.

## File inventory and preparation

The platform's private organizer input, `raw_dataset.zip`, contains exactly `dataset_public.zip` and `private_answers.jsonl`. `private_answers.jsonl` carries one private grading record per test case and must not be shown to participants. Prepare extracts the participant archive into the public directory, converts the private records to `answers.csv` in the private directory, and creates public `sample_submission.csv`. The participant archive, also available at the dataset link below, contains exactly:

- `train.jsonl`: 4,000 newline-delimited JSON training episodes with supervised labels.
- `test.jsonl`: 1,000 newline-delimited JSON test episodes with public goals but without oracle programs, outcomes, or evidence.
- `manifest.json`: a compact dataset metadata record with `train_cases: 4000`, `test_cases: 1000`, `events_per_case: 360`, `topics: 20`, `split: "held-out regime pairings"`, `provenance: "creator-owned deterministic synthetic event corpus"`, and `license: "CC-BY-4.0"`. It contains no labels, seed, or per-case answers.
- `LICENSE_DATA.md`: the CC BY 4.0 notice for the generated dataset and documentation. It gives the license URL and suggested attribution, asks redistributors to link to the public source and indicate changes, and clarifies that private answers, generator, grader, and software code are outside this data-license grant.

The public prepared directory additionally contains `sample_submission.csv`; it is generated by Prepare and is not a member of `dataset_public.zip`. The participant ZIP is 299,527,818 bytes (about 300 MB). The source release contains this ZIP only; GitHub's automatic repository source archive is not the dataset.

## Known limitations

All episodes, notes, roles, review markers, goals, and outcomes are generated. They do not model the full ambiguity, language variety, privacy issues, or changing user intent in real conversations. The public goal rule is deliberately narrow and its exact optimum can be computed by enumerating 56 ordered pairs, so this benchmark measures rule execution and evidence tracking rather than uncertain prediction of a real person's intent. Training and test differ by held-out *combinations* of reliability and drift regimes, but both are drawn from the same generator, schema, vocabulary, and event length. A score on this split does not establish performance on unseen generators, languages, real users, or production memory systems. The benchmark evaluates four queries after fixed-length episodes, not long-running agents with tool failures, consent handling, deletion requests, or adversarial instructions. The data should not be used to infer that a hook policy is safe to deploy without separate real-world evaluation.
